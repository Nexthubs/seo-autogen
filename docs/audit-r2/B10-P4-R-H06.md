> 状态：✅ 完成（新增迁移 `0012_evidence_support_check`）

## 1. 问题

审计复现：

```
捏造论文/97% 数字 + 一个只返回欢迎词的来源页面
→ evidence 仍为 high / supported
```

- 位置：`app/services/evidence_verification.py:66–84`；事实审核仍以 Evidence Notes 作为唯一事实输入。
- Spec：§18（禁止编造论文/统计；事实来源不得由竞品声明替代）；
  内容规则要求引用研究经核实。

### 根因

H09 的核实只做了"能不能抓到、正文是否非空"：

```python
if not content:
    return False, "empty content"
return True, "ok"          # ← 只要有字就算"已核实"
```

它验证的是**链接可达**，不是**来源支持该结论**。真实网址（甚至一个完全无关的首页）
同样返回非空正文，于是模型自述的论文题名、统计数字、`high/supported` 全部原样放行。

## 2. 修复设计：4 条确定性核实规则

新增纯函数 `assess_source_support(note, page) -> SupportCheck`，比对**抓取正文**
与**提议的 note**：

| # | 规则 | 判定 | 说明 |
|---|---|---|---|
| 1 | **反驳检测** | `contradicted` | claim 显著词所在句子出现 `no evidence` / `debunked` / `not supported` / `myth` / `refute` 等否定标记 → 来源在反驳该结论 |
| 2 | **来源题名印证** | `unsupported` | `source_title` 的非通用词（排除 study/research/journal/university…）或年份须出现在页面（标题或正文），否则"论文题名不符" |
| 3 | **数字印证** | `unsupported` | claim 中每个统计数字必须出现在正文，兼容 `97 %` / `97 percent` / `0.97` 等拼写；缺失即"无对应数字" |
| 4 | **主题词重合** | `unsupported` | claim 显著词（≥4 字符、去停用词）在正文占比 ≥ `MIN_TERM_OVERLAP=0.25`，否则"可达但不相关" |

判定优先级：`反驳 > 题名 > 数字 > 重合 > supported`。

### 降级映射与落库

| `verification_status` | confidence | usage | note 标记 |
|---|---|---|---|
| `supported` | 不变 | 不变 | note 不变 |
| `unsupported` | `low` | **`soften`** | `source_unsupported: <reason>` |
| `contradicted` | `low` | **`avoid`** | `source_contradicted: <reason>` |
| `unverified`（缺失/抓不到/空正文） | `low` | **`avoid`** | `source_unverified: <reason>` |

**所有**判定都保存：
- `evidence_notes.verification_status`（VARCHAR(16)）
- `evidence_notes.supporting_excerpt`（TEXT，印证或反驳的原句，截断 400 字符）

这两个字段随 **Writer / Fact Reviewer 上下文**（`load_research_context`）、
**Job Detail**（`routes/jobs.py`）、**§34 本地导出**（`job_artifacts.py`）一起暴露，
使"为什么这条 note 被信任"可审计。
