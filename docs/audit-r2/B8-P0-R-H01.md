## 1. 问题（审计原文摘要）

- 位置：`app/workers/article_tasks.py:98`、`:112`
- Spec：§9、P8（浏览器关闭后 Worker 继续工作）、P9（Provider/Job timeout）
- 实际：`Queue.enqueue(..., timeout=3600)` 中 `timeout` **不是** RQ 的 enqueue 控制参数。
  RQ 2.12.0 `Queue.parse_args` 只提取 `job_timeout`，传入的 `timeout` 会被当作任务
  kwargs 下发；`process_job(job_id, options)` 与 `sync_strapi_draft(job_id)` 都不接受
  该参数，任务在**进入函数体之前**即抛 `TypeError: unexpected keyword argument 'timeout'`。
- 影响：业务失败落库逻辑不会执行，`generation_jobs.status` 可能长期停留 `queued`，
  UI 看不到任何失败原因。
- 为什么既有测试没发现：`tests/unit/test_h08_rq_timeout.py` 用 fake queue 只记录
  `kwargs["timeout"]`，反而"确认"了错误调用，从未让真实 RQ 解释参数。

## 2. 根因

RQ 的控制参数与控制参数名是一组固定白名单，由 `Queue.parse_args` 从 kwargs 中弹出：

```
job_timeout, description, result_ttl, ttl, failure_ttl, depends_on, job_id,
at_front, meta, retry, repeat, on_success, on_failure, on_stopped,
webhooks, pipeline, unique
```

`timeout` 不在其中。因此 `timeout=3600` 一路进入 `EnqueueArgs.kwargs`
（即任务关键字参数），并在 worker 绑定函数签名时失败。

## 3. 修复内容

### 3.1 代码

| 文件 | 改动 |
|---|---|
| `app/workers/article_tasks.py` | `enqueue_job`：`timeout=settings.rq_job_timeout_seconds` → `job_timeout=settings.rq_job_timeout_seconds`，并补充注释说明 RQ 参数名（引用 `Queue.parse_args`）与回归编号 R-H01 |
| `app/workers/article_tasks.py` | `enqueue_strapi_sync`：同上改为 `job_timeout=` |
| `app/core/config.py` | `rq_job_timeout_seconds` 的 docstring 注释从"显式传 timeout"更正为"作为 RQ 的 `job_timeout` 控制参数显式传入（audit H08 / R-H01）" |

未新增/修改任何 Provider Interface、数据库结构或 pipeline 步骤。

### 3.2 回归测试（审计要求的验收方式）

审计明确要求："测试经过真实 RQ 参数解析/Job 创建，断言 job timeout 是配置值、
任务 kwargs 不含 timeout，再校验两个 callable 能绑定参数。"

`tests/unit/test_h08_rq_timeout.py` 因此整文件重写：

1. `FakeQueue` 仅用于**捕获**项目 helper 交给 `queue.enqueue` 的真实 `args/kwargs`
   （不触碰 Redis）；
2. `_parse_real_rq()` 把捕获结果交给**已安装 RQ 的 `Queue.parse_args`**，
   由真实 RQ 语义决定 timeout 与任务 kwargs；
3. `_resolve_task()` 按 RQ 的 dotted path 规则导入真实 callable，
   用 `inspect.signature(task).bind(*parsed.args, **parsed.kwargs)` 证明 worker
   能进入函数体。

| 用例 | 断言 |
|---|---|
| `test_enqueue_job_uses_rq_job_timeout` | `parsed.timeout == 4321`；`"timeout" not in parsed.kwargs`；`parsed.args == (job_id, {})`；签名绑定成功 |
| `test_enqueue_job_with_options_binds_and_keeps_timeout` | retry options 作为第 2 位置参数；timeout 仍为 4321；绑定成功 |
| `test_enqueue_strapi_sync_uses_rq_job_timeout` | 单参数任务；timeout 4321；绑定成功 |
| `test_rq_parse_args_rejects_plain_timeout_kwarg` | **防漂移**：若将来 RQ 开始消费 `timeout`，本用例失败并提示重新评估 R-H01 结论；当前证明 `timeout=` → `parsed.timeout is None` + kwargs 含 `timeout` + 绑定抛 `TypeError` |
| `test_setting_defaults_to_one_hour` | 默认 3600 秒 |
