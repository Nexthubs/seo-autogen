## 1. 问题

### R-H05 — DoD 仍放行空 FAQ、有效 H1 和旧 writer 的审核（High）

审计三类可复现漏检：

1. `_faq_question_count` 只数 `###`，不检查对应答案 → 三个空标题可过 gate；
   且测试 `test_faq_empty_answers_do_not_lower_count` 明确接受该行为。
2. H1 正则漏掉 CommonMark 允许的 **1–3 空格缩进 ATX H1** 与 **单 `=` Setext H1**
   （`X\n=\n`）；项目 Markdown 渲染器把二者都渲染为 `<h1>`，gate 却返回无错误。
3. `job_reviews` 按整个 job 聚合，未限制当前 writer：新 writer v3/revision v4 没有
   本轮 seo/fact/style，只要旧稿有三类 review 并给 v4 写 anticopy 也会通过。

### R-M03 — 审核步骤重跑删除旧 Review（Medium）

`persist_review` 对相同 (writer/version/type) **先 delete 旧行再 insert**。已有 revision
保留下来，但产生它的原审核结果消失。审计复现：同一 writer 的 fact review 连续保存
`ORIGINAL` 与 `REPLACEMENT` 后，原 review ID 不再存在。

## 2. 修复设计

### 2.1 R-H05：H1 / FAQ 改用 Markdown token 解析

审计要求"以 Markdown token 解析判定标题和问答"。引入与预览渲染器同一解析器
（`MarkdownIt("commonmark")`）：

| 判定 | 旧实现 | 新实现 |
|---|---|---|
| H1 | `^#\s(?!\s)` + `={2,}` Setext 正则 | `_headings(body)` 收集 `heading_open` token，`tag == "h1"` 即违规 —— 覆盖缩进 ATX / 单 `=` Setext；**不包含 raw HTML `<h1>`**；fenced code 内的 `#` 不误报 |
| FAQ 题数 | 数 `###` 行 | `_find_h2(headings,"faq")` + 区间内 `h3` 计数 |
| FAQ 答案 | 不检查 | `_faq_qa_counts()`：每个 `###` 之后、下一个 heading 之前必须存在**非空 `inline` 内容块**（段落 / 列表项 / 引用都算） |

失败信息：`article: body_markdown contains an H1 heading ('…')`、
`article: FAQ has N question(s) without an answer`。

### 2.2 R-H05：审核必须挂在当前 writer 草稿

```python
writer_version = latest_writer_version(session, job)
for rtype in ("seo", "fact", "style"):
    row = latest_review_row(session, job, writer_version, rtype)
    if row is None:
        errors.append(f"article: missing {rtype} review for the current writer draft v{writer_version.version}")
```

reviser 修订的正是 `latest_writer_version`，所以"审核挂在当前 writer"等价于"审核是
本次 revision 的输入"。旧稿的 review 作为历史保留但不再满足 gate。

### 2.3 R-M03：append-only 审核历史 + revision 输入固化

```
article_reviews.attempt           第 N 次运行；当前有效 = max(attempt)
article_versions.based_on_reviews {"seo": {"review_id": "...", "attempt": 1}, ...}
```

- `persist_review` **不再 delete**：`attempt = max(attempt)+1` 追加。
- `latest_review_row()` / `latest_review()`：按 attempt desc 取"当前有效"。
- `review_lineage()`：返回当前 attempt 集合；reviser 把它写入新 revision 的
  `based_on_reviews`，因此即使之后重跑 Fact Review，旧 revision 仍能定位它当时
  使用的审核集合（审计验收："旧 revision 和新 revision 各自输入"）。
- DoD 的 anticopy 判定同样取 final 版本的最高 attempt。
