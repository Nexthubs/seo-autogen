## 1. 问题

### R-H02 — Upload 顶层数组 + 异常绕过失败状态（High）

- 位置：`app/providers/cms/strapi_cms.py:368–397`；`app/pipeline/steps/strapi_sync.py:419`。
- 复现：`StrapiCMSProvider._upload_result([{'id':101,'url':'/uploads/hero.webp'}])`
  → `AttributeError: 'list' object has no attribute 'get'`。

标准 Strapi upload controller（`uploadFiles`）把文件列表直接放到 `ctx.body` 并返回
**HTTP 201 + 顶层数组**：

```json
[{"id": 101, "url": "/uploads/hero.webp", "documentId": "..."}]
```

旧解析从 `data.get("data")` 开始，只认可 `{data:[...]}` 包裹，因此真实响应必然崩溃。
更严重的是该 `AttributeError` 不是 `PipelineError`，`run_strapi_sync` 只捕获
`PipelineError`，异常直接逃出：sync row 停留 `in_progress`、job 停留 `strapi_syncing`，
Worker 仅记录 crash（无法解释、无法重试）。

### R-H03 — 有失败行但无 documentId 时重试产生重复行（High）

- 位置：`app/pipeline/steps/strapi_sync.py:174–180`、`:216–228`。
- 复现：首次缺 author/category 前置校验失败 → 创建 `StrapiSyncRow(job_id, documentId=None)`；
  补齐配置后重试，条件 `row is None or existing_doc_id is None` 成立 → 远端创建 Draft 后
  **又新建一个同 job_id 的行** → `UNIQUE constraint failed: strapi_syncs.job_id`；
  rollback 后原行 `documentId` 仍为空。

## 2. 修复设计

### 2.1 `_upload_result`：标准形状优先

```python
top-level list      -> items = data                      # 标准 Strapi 5（201）
{"data": [...]}     -> items = payload                   # 代理/包裹兼容
{"data": {...}}     -> items = [payload]                 # v4 单对象
裸对象               -> items = [data]
其它/空              -> items = []  -> PipelineError(STRAPI_SCHEMA_MISMATCH)
```

新增 `_safe_json()` 做错误 raw 的容错序列化（list/dict/scalar 均可，绝不抛异常），
配合 B9 的 `PipelineError` raw 归一化形成完整的安全链。

### 2.2 `run_strapi_sync`：未知异常也落统一失败态

```python
except PipelineError as error:
    _persist_sync_failure(... error.error_code.value ...)
    raise
except Exception as error:
    logger.exception("strapi_sync_crash")
    session.rollback()            # 不再继续使用可能已失败的事务
    _persist_sync_failure(
        session, job, row,
        error_code="UNEXPECTED",
        message=f"{type(error).__name__}: {error}",
        raw=<traceback>,
    )
    raise
```

`_persist_sync_failure()`（单入口）：

- 无行则创建；有行则复用（重查 job_id，绝不双插）；
- row → `failed` + `error_message`（脱敏），**保留 `strapi_document_id`**（§41 幂等锚）；
- job → `strapi_sync_failed` + `error_code` / `error_message` / `error_raw`（脱敏）/`completed_at`；
- commit + warning 日志。

### 2.3 R-H03：区分"无行"与"有行但无 ID"

```python
if row is None or existing_doc_id is None:
    entry = await provider.create_draft_entry(payload)
    if row is None:
        row = StrapiSyncRow(...); session.add(row)
        try:
            session.flush()
        except IntegrityError:      # 行在下方出现：rollback → 重查 → 复用

        row.strapi_document_id = entry.document_id

```
